# LeadBridge AI — مهدیار هوش‌افزا

سیستم **مولتی‌ایجنت جذب و تحویل لید** برای برند مهدیار هوش‌افزا. کسب‌وکارهای هدف را پیدا می‌کند، راه‌های ارتباط مجازی‌شان را استخراج می‌کند، درد اصلی‌شان را تحلیل و امتیازدهی می‌کند، و برای لیدهای مناسب یک **پیام عمیقاً شخصی‌سازی‌شده** — بر پایه‌ی هویت برند مهدیار — آماده می‌کند تا پس از **تأیید انسانی** ارسال شود.

> استک: **Next.js 14 + Vercel AI SDK + OpenRouter + Supabase** · TypeScript · Tailwind.
> این پروژه بازطراحیِ یک سیستم مولتی‌ایجنت است؛ کد نسخه‌ی قبلی (بلاگ) در `_archive/blog/` نگه داشته شده.

---

## معماری (خلاصه)

هر جزء یا **Agent** (LLM: تحلیل/قضاوت) است یا **Service** (کد قطعی: محاسبه/قاعده). ارکستریتور خودش کد قطعی است، نه LLM.

```
کشف لید (Google Maps) → استخراج کانال‌های ارتباط → اعتبارسنجی/حذف تکراری
  → تحلیل (درد اصلی) → امتیازدهی (۷ معیار وزنی، آستانه ۷۰)
  → انتخاب خدمت (از ۷ خدمت مهدیار) → انتخاب نمونه‌کار
  → نوشتن پیام ⇄ نقد پیام (≤۲ دور) → Policy Guard
  → پیش‌نویس + تأیید انسانی → ارسال → تحویل (Handover)
  → درس‌گیری خودبهبودی
```

**اصول کلیدی:** فقط داده‌ی عمومی از رابط‌های مستند — بدون اسکرپ نامحدود، بدون دایرکت سرد انبوه، بدون خودکارسازی با سشن لاگین‌شده؛ پیام همیشه پیش‌نویس + تأیید انسانی؛ بدون قیمت/تخفیف/قرارداد؛ شخصی‌سازی مبتنی بر درد واقعی هر بیزینس.

## ساختار

```
src/lib/
├── brand.ts        ← هویت برند مهدیار: ۷ خدمت، پرسوناها، لحن، کلمات مجاز/ممنوع، نمونه‌کارها
├── config.ts       ← بازارهای هدف (ICP)، وزن‌های امتیاز، روبریک نقد، سقف‌ها، اولویت کانال
├── ai.ts           ← هسته: OpenRouter + runAgentJSON/Text (اعتبارسنجی Zod + retry)
├── store/          ← لایه‌ی CRM (الگوی Adapter: Supabase یا حافظه)
├── discovery.ts    ← جریان کشف لید (پیشرونده، با مکان‌نمای هر کمپین)
├── integrations/   ← OpenStreetMap · Google Places · Tavily · جست‌وجوی گوگل · اینستاگرام · استخراج کانال
├── agents/         ← ایجنت‌ها و سرویس‌های قطعی + ارکستریتور
└── audit.ts        ← دفترچه‌ی تصمیم
supabase/schema.sql     ← اسکیمای کامل CRM + seed نمونه‌کارها
supabase/migrations/    ← تغییرات بعدی؛ **اول SQL را اجرا کن، بعد کد را پوش کن**
```

## راه‌اندازی

```bash
npm install
cp .env.local.example .env.local   # مقادیر را پر کنید
npm run dev                        # http://localhost:3000
```

برای ذخیره‌سازی دائمی، `supabase/schema.sql` را در SQL Editor پروژه‌ی Supabase اجرا کنید. متغیرهای محیطی لازم در `.env.local.example` توضیح داده شده‌اند.

## وضعیت ساخت

**هر پنج فاز نقشه‌راه ساخته شده و کار می‌کند:** کشف لید، استخراج کانال، تحلیل، امتیازدهی، انتخاب خدمت و نمونه‌کار، نویسنده‌ی پیام، منتقد، نگهبان سیاست، درس‌نویس.

بیرون از نقشه‌راه هم ساخته شد:

- **CRM** — قیف تبدیل، آمار هر کمپین، پیگیری‌ها (`/studio/crm`).
- **دفترچه‌ی تصمیم** — هر تصمیم انسانی و ماشینی ثبت می‌شود.
- **گفت‌وگو و پیگیری** — وضعیت پاسخ، لحن، اقدام بعدی.
- **حذف نرم + سطل زباله با بازگردانی** (`/studio/trash`).
- **کشف پیشرونده** — هر بار زدن «کشف لید» بخش تازه‌ای از شهر و نقشه‌ی جست‌وجو را می‌گردد.

### منابع کشف

| منبع | کلید لازم | بدون کلید |
|---|---|---|
| OpenStreetMap (Nominatim + Overpass) | ندارد | همیشه فعال — منبع پیش‌فرض |
| Tavily | `TAVILY_API_KEY` | بی‌صدا رد می‌شود |
| Google Programmable Search | `GOOGLE_SEARCH_API_KEY` + `GOOGLE_SEARCH_ENGINE_ID` | بی‌صدا رد می‌شود |
| Google Places (New) | `GOOGLE_MAPS_API_KEY` | OSM جایش را می‌گیرد |
| Instagram Graph | `IG_ACCESS_TOKEN` + `IG_BUSINESS_ID` | غنی‌سازی انجام نمی‌شود؛ فیلد دستی `igNote` جایگزین است |

هیچ منبعی نبودِ کلیدش را به شکست کل کشف تبدیل نمی‌کند.
